# overdosecd

A smart directory and project jumper for the terminal. It remembers the repositories and folders you actually work in, so you can jump to them without typing long paths.

```sh
ocd over
```

instead of:

```sh
cd ~/code/projects/rust/overdosecd
```

Local-first: no cloud, no account, no telemetry. Your index is a plain file you can read, edit, and back up.

## Install

- `cargo install overdosecd` — or `cargo install --git https://github.com/Dead-Abyss/overdosecd`, or `cargo install --path .` from a checkout

Requires Rust 1.99 or newer. Linux is the only supported platform — the crate refuses to build anywhere else — and no pre-built binaries are published: `cargo install` always builds from source. The binary is `overdosecd`; the `ocd` command is a shell wrapper generated by `overdosecd init`.

## Shell setup

Add one line to your shell config and restart the shell:

```sh
# zsh (~/.zshrc) or bash (~/.bashrc)
eval "$(overdosecd init zsh)"    # or: overdosecd init bash
```

```fish
# fish (~/.config/fish/config.fish)
overdosecd init fish | source
```

`ocd` understands a small grammar:

| Invocation | What happens |
| ---------- | ------------ |
| `ocd` | opens the picker |
| `ocd <query>` | jumps when the match is confident, otherwise opens the picker with the query typed in |
| `ocd <subcommand> …` | runs the CLI (`add`, `list`, `info`, `doctor`, …) |
| `ocd --cmd <anything>` | runs the CLI and nothing else: no picker, never a `cd` |
| `ocd goto <name>` | jumps to a project whose name collides with a subcommand |

Subcommand names are reserved by the wrapper, so a project actually named `tag`, `list`, or `ui` needs `ocd goto <name>`.

`init` also registers `ocd <TAB>` completion: subcommands first, then indexed names, aliases, and tags; `--no-track` completes after a query. Missing projects are not offered. On zsh, the `eval` line should come after `compinit` — before that, registration is skipped silently.

Completion for the `overdosecd` command itself (subcommands and flags) is a separate script:

```sh
overdosecd completions bash > ~/.local/share/bash-completion/completions/overdosecd
overdosecd completions zsh  > ~/.zfunc/_overdosecd                    # a directory on your $fpath
overdosecd completions fish > ~/.config/fish/completions/overdosecd.fish
```

## Commands

| Command | What it does |
| ------- | ------------ |
| `add [PATH] [--name N] [--alias A] [--tag T] [--force]` | index a directory (defaults to `.`); `--force` refreshes the stored git remote and project kind |
| `list [--sort used\|name\|created] [--type T] [--since WHEN] [--all] [--json]` | what you have indexed; `--type rust` filters by project kind, `--since 7d` or `--since 2026-09-01` by last jump |
| `goto <query> [--no-track]` | print the best matching path (stdout only); `--confident` exits `1` instead of acting on a fuzzy-only match |
| `info <query>` | details for one project |
| `remove <query> [--yes]` | drop a project from the index |
| `pin <query>` / `unpin <query>` | keep a project at the top of `list` |
| `rename <query> <name> [--force]` | rename a project |
| `alias add\|remove <query> <alias>` | add or remove another name to match |
| `tag add\|remove <query> <tag>` | add or remove a tag |
| `scan <roots>…` / `scan --home [--refresh] [--dry-run] [--max-depth N]` | preview directories with the discovery walk, writing nothing to the index |
| `import zoxide\|autojump\|zsh-z [--dry-run] [--min-score N] [--limit N]` | bring another jumper's history over |
| `ui [--query TEXT] [--no-track]` | the interactive picker (see below); `ocd` and `ocd --ui` run this |
| `doctor [--fix] [--refresh]` | check the index; `--fix` repairs stale projects interactively |
| `migrate` | move a JSON index to the SQLite backend |
| `init bash\|zsh\|fish` | print the `ocd` wrapper and completion setup |
| `completions bash\|zsh\|fish` | print a completion script for the `overdosecd` command itself |

A few examples:

```sh
overdosecd add ~/notes --name notes --alias n --tag writing
overdosecd list --all --since 30d
ocd over                    # exact, prefix, alias, tag, repo, or fuzzy match
ocd --cmd list                # same as `overdosecd list`; no picker, no cd
cd "$(overdosecd goto over)"  # goto prints only the path, so it is safe to script with
```

When a path is longer than your terminal, `list` elides the middle (`~/code…/overdosecd`) and keeps the identifying final component; piped output is never truncated. Names, aliases, tags, and paths must be printable — control characters are refused at every entry point, and `doctor` reports entries that predate that guard.

## Jumping

`ocd <query>` jumps when the index is sure and asks when it is not:

- **exact and prefix matches** — project name, alias, tag, or repo name — jump straight away (classes under [Matching](#matching))
- **everything else opens the picker with the query typed in**: a fuzzy-only match, an ambiguous query, no match, or a vanished directory

`overdosecd goto <query>` never opens a picker — that is what scripts get — and `goto --confident` is the flag behind the wrapper: it exits `1` instead of jumping on a fuzzy-only match. Anywhere stdin is not a terminal, `ocd <query>` behaves exactly like `goto`, messages and exit codes included, so nothing scriptable becomes interactive.

## Matching

Queries are compared against project names, aliases, tags, path components, and Git remotes, in this order:

1. exact name
2. exact alias
3. name prefix
4. alias prefix
5. tag
6. fuzzy name / alias / path (subsequence matching)
7. Git repo name and `owner/repo` slug

Ranking adds bonuses for pinned, recently used, and frequently used projects, Git repositories, and shallower paths. If the top two candidates are too close to call, `overdosecd` refuses to guess and prints the candidates with exit code `1`.

Type more words to narrow a query: every word must match the project, each contributes its own best signal to the score (bonuses apply once), and a name containing spaces still matches the whole query exactly. For `ocd`, a multi-word query only jumps without asking when *every* word lands in the confident classes above — one fuzzy word and the picker opens with the words prefilled.

Every successful jump records `last_used_at` and `use_count`, which feed the recency and frequency bonuses; on SQLite each jump also appends to the `usage` log behind `info` and `list --since`. `--no-track` skips recording.

`--debug` prints every ranked candidate to stderr with its match reason and score; stdout is untouched, so `goto` stays safe for `cd "$(…)"`. It only says anything for the commands that resolve a query: `goto`, `info`, `remove`, and the index mutations.

```text
$ overdosecd --debug goto over
debug: 2 candidates for `over`
  1. overdosecd -> ~/code/overdosecd (exact name, score 9836)
  2. over-utils -> ~/code/over-utils (name prefix, score 1816)
```

## Picker

Bare `ocd` opens an interactive picker; `ocd --ui` and `overdosecd ui` are the same thing. Typing filters the list with the same ranked matcher a query uses, so what looks like a jump is one keystroke away.

The picker draws a compact box inline, right where the cursor was: it never takes the screen over, your scrollback stays put, and the box is erased when it exits, so your next prompt lands on the line the box was on. By default it is ten rows tall — the list, the input line, and a hint or status line — and it never hides the whole terminal.

| Key | Action |
| --- | ------ |
| typing | filter the list (same ranking as `ocd <query>`) |
| `Tab` | switch between the search box and the list mode |
| `j` / `k`, `↑` / `↓`, `g` / `G`, `u` / `d`, PgUp / PgDn | move the highlight (arrows and PgUp/PgDn work while typing too) |
| `Enter` | jump to the highlighted project |
| `Ctrl+p` | pin or unpin |
| `Ctrl+a` | add a directory; the prompt is prefilled with the typed query, or the current directory |
| `Ctrl+x` | remove from the index (asks `y/N` first) |
| `m` | mark or unmark the highlighted row (list mode) |
| `Ctrl+Space`, or `:` in list mode | open the action palette |
| `?` | key help (list mode) |
| `Esc` / `Ctrl+c` | cancel (exit `1`, nothing on stdout), or close whatever is open |
| wheel / click | move the highlight / select the row under the pointer |

In list mode `j` and `k` only move the highlight; `Tab` (or `i` / `/`) returns to the search box. `*` marks pinned projects, `!` marks missing ones (Enter refuses those), and every row shows the path and, once used, how long ago.

The action palette is the rest of the CLI inside the picker. Type to filter, `j`/`k` to choose, `Enter` to run:

- **pin / unpin**, **add**, **remove** — the chords above
- **rename**, **alias ±**, **tag ±** — one-line prompts
- **toggle details** — path, aliases, tags, remote, use count, live branch, recent jumps
- **sort**, **hide or show missing projects**, **health** (`Enter` relocates, `x` removes, `r` re-checks), **migrate to SQLite**, **help**, **quit**

`m` marks rows and turns pin/remove/tag/alias into batches: one prompt per batch, and a fully pinned batch unpins. The picker writes only the chosen path to stdout, so `cd "$(overdosecd ui)"` works exactly like `goto`. It needs a controlling terminal — stdout may be the wrapper's pipe — and exits `1` with a clear error without one. Colors follow the usual flags, except that `auto` keys off the terminal rather than stdout. The mouse is captured in a plain terminal and left alone inside a multiplexer (tmux, zellij, screen), where it would suspend the pane's own UI — `[ui] mouse = "always"` forces it on.

## Home search

When the index has nothing for what you typed, the picker looks under `$HOME` instead. Matches show with a `~` marker and a `home` tag, enter jumps to one (nothing is recorded — it is not in the index), and `Ctrl+a` opens the add prompt prefilled with its path. The palette's **also search home directories** shows them even when the index did match.

The walk is bounded and never indexes: no symlink following, a built-in skip list (`.git`, `node_modules`, `.cache`, `target`, `dist`, `build`, `.venv`, …), `[discovery] max_depth`, and at most `max_entries` cached directories, preferring shallow and project-like ones (a `.git`, `Cargo.toml`, `package.json`, `pyproject.toml`, or `go.mod`). The cache is `home-dirs.json` next to your index (`0600`, atomic, rebuildable); it loads lazily on the first missed query and refreshes in the background past `ttl_hours`, showing `scanning home…` while it does.

```sh
overdosecd scan --home            # build/refresh the cache now
overdosecd scan ~/code/scratch    # preview explicit roots: best candidates first, project-like marked
```

`--home` and explicit roots are exclusive, `--refresh`/`--dry-run` are cache-only, and a missing root is a clean error. Explicit roots write neither the cache nor the index.

## Import

Arrive with an index instead of building one by hand:

```sh
overdosecd import zoxide      # ~/.local/share/zoxide/db.zo (or $_ZO_DATA_DIR)
overdosecd import autojump    # ~/.local/share/autojump/autojump.txt (or $AUTOJUMP_DATA_DIR)
overdosecd import zsh-z       # $ZSHZ_DATA, default ~/.z (the rupa/z format)
```

Source stores are read, never written. Frecency maps onto `use_count`, and timestamps onto `last_used_at` when the format carries one; autojump's negative weights are blacklist markers and are skipped. Entries dedupe by canonical path, so re-running imports nothing new, and imports carry counters only: `info` history and `list --since` never claim jumps that did not happen here.

`--dry-run` prints the exact `list` table it would produce and writes nothing; `--min-score N` drops low scores and `--limit N` keeps the highest. A missing store is a one-line error naming the path tried.

## Configuration

overdosecd works with zero configuration. To tune it, write `~/.config/overdosecd/config.toml`:

```toml
[general]
color = "auto"          # auto | always | never
hook = false            # install a cd wrapper that records jumps into indexed projects
hint = false            # ...and one-line hints to `ocd add` directories you visit often

[matching]
fuzzy = true            # subsequence matching on names, aliases, paths, remotes
recency_max = 800       # maximum bonus for a just-used project
frequency_max = 400     # ceiling of the use-count bonus
pinned_bonus = 1500     # bonus for a pinned project
ambiguity_margin = 150  # score gap below which a query is ambiguous
depth_penalty = 20      # penalty per path component

[ui]
height = 10             # picker rows: list + input + hints (clamped to the terminal)
border = false          # draw a border around the picker box
mouse = "auto"          # auto | always | never (auto: off inside a multiplexer)

[discovery]
home = true             # search $HOME when the index has no match
max_depth = 8           # how deep the walk goes, relative to $HOME
max_entries = 50000     # cache cap; shallow and project-like directories win
ttl_hours = 24          # background refresh once the cache is older
skip = ["my-scratch-dir"]  # extra directory names to skip, on top of the defaults

[storage]
backend = "json"        # json | sqlite
```

Every key is optional and the defaults above are the built-in behavior. Unknown keys and negative numbers are rejected with a clear error (exit `3`) rather than silently ignored.

`hook = true` makes `init` install a `cd` wrapper: a plain `cd` into an indexed project records the jump like a tracked `goto`, so recency and frequency reflect how you really move around. `hint = true` counts visits to unindexed directories in `hook-visits.json` (private, atomic, rebuildable) and prints one `ocd add` suggestion on the third visit in a month. Nothing is indexed automatically, `cd`'s behavior and exit status never change, and `ocd`'s own jumps use the builtin so nothing is recorded twice. If another tool already wraps `cd`, enable this knowingly — one function wins.

The color mode resolves in this order: `--color WHEN`, then `OVERDOSECD_COLOR`, then `color` in the file, then `auto` (colorize on a terminal, honoring `NO_COLOR`). Point overdosecd at a different config file with `OVERDOSECD_CONFIG=/path/to/config.toml`; that file must exist, and `doctor` reports an unreadable one as an issue.

## Storage

The index lives in a versioned JSON file (`projects.json`) by default. The optional SQLite backend adds a real jump log and updates only the rows a mutation touches.

Move an existing JSON index over with `overdosecd migrate`: it writes `projects.db` in one transaction and keeps the original as `projects.json.migrated-<timestamp>`. It is safe to run twice, and it refuses to overwrite a database that already holds projects. When the configured backend is still `json`, it prints the `[storage]` snippet so you can switch over.

Both backends keep the same matching, ranking, and output behavior. On SQLite, `info` gains a `history:` line with the latest jumps, `list --since` reads the same log, data files are created `0600` with WAL journalling (`projects.db-wal` and `projects.db-shm` appear while overdosecd runs), and the jump log keeps the latest 500 jumps per project.

## Git awareness

When you add a Git working tree, overdosecd indexes its remote (`origin`, or the first configured remote) and can jump by it — even when the project is named something else:

```sh
ocd widgets                   # the repository name
ocd acme/widgets              # the full owner/repo slug
```

`info` shows live details:

```text
type:      rust
git:       yes
branch:    main
remote:    origin git@github.com:Dead-Abyss/overdosecd.git
```

The remote is a snapshot taken at `add`; refresh it with `overdosecd doctor --refresh` (or `overdosecd add --force <path>`) after changing it. Worktrees are understood (branch from the worktree, config from the main repository), `include.path`/`includeIf "gitdir:…"` config includes and `url.<base>.insteadOf` rewrites are honored, and bare repositories are detected. The org/owner alone is not searchable. Projects also remember their kind — `rust`, `node`, `python`, `go`, or `unknown`, from marker files at `add` — shown as `type:` and filterable with `list --type`.

## Health check

`overdosecd doctor` reports index problems and exits `1` when it finds any:

```text
$ overdosecd doctor
index: ~/.local/share/overdosecd/projects.json (3 projects)
storage: json
config: ~/.config/overdosecd/config.toml

issues (2):
  - stale: `old-experiment` -> ~/code/old-experiment (directory no longer exists)
  - duplicate name: `app` is used by 2 projects; queries for it are ambiguous (`overdosecd rename`)

hint: `--fix` repairs stale projects interactively; `--refresh` updates stored metadata
```

It checks for stale paths, duplicate names, quarantined index files, permission problems (index, home cache, data directory), indexed values containing control characters, and an unreadable config file. Quarantined files are reported, never deleted.

On SQLite it also reports the schema version, orphaned `projects.db-wal`/`-shm`/`-journal` files whose database is gone (`stray:`), a JSON and SQLite pair holding different projects (`mismatch:`), and an unreadable inactive index (`unreadable:`). Everything is read-only: the inactive index is inspected, never quarantined, migrated, or rewritten.

`--fix` walks each stale project and lets you skip it, remove it, quit, or type a replacement path; repairs are applied under the lock and the git remote is re-detected. It needs a terminal, so it refuses to prompt in scripts. `--refresh` re-reads the stored metadata (git remote, project kind) of every indexed project, which is useful after `git remote set-url`.

## Data

```text
~/.local/share/overdosecd/projects.json   # your index (default JSON backend)
~/.local/share/overdosecd/projects.db     # your index when backend = "sqlite"
~/.config/overdosecd/config.toml          # optional configuration
```

The locations follow the XDG directories. `--data-dir` / `OVERDOSECD_DATA_DIR` override the index location, `OVERDOSECD_CONFIG` the config file; both must be **absolute**, since a relative value would resolve against the current directory and could let a planted folder choose which index is read and written. The data directory is created `0700`, the JSON index is written atomically, and an unreadable index is moved aside to `projects.json.corrupt-<timestamp>` rather than silently wiped.

## Exit codes

| Code | Meaning |
| ---- | ------- |
| 0 | success |
| 1 | no match, ambiguous query, or invalid user input |
| 2 | command-line usage error |
| 3 | I/O, storage, or configuration error |

`overdosecd doctor` uses the same table: `0` when the index is healthy, `1` when it reports issues, `3` when the index cannot be read. The picker uses `1` for both cancelling and refusing to run without a terminal, and prints nothing on stdout in either case.

```sh
cargo uninstall overdosecd
rm -rf ~/.local/share/overdosecd
```

and remove the `eval` line from your shell config.
